# Log a WARN when the pr-state cache write in observePRState fails

## Problem

`observePRState` performs a best-effort side-effect write into the per-PR
cache and swallows every failure in an empty `catch` at
`engine/pipeline/primitives/observe-status.ts:239-241`:

```ts
if (deps.kv && deps.ctx) {
  try {
    await recordTerminalPRStates(closed, deps.kv, deps.ctx);
  } catch {
    // Cache write is non-critical; swallow errors.
  }
}
```

`recordTerminalPRStates` (`engine/pipeline/primitives/pr-state-cache.ts:30-54`)
loops `kv.get` + `kv.put` over every terminal PR, so a mid-loop rejection
leaves `kv:pr-states/*` partially written while the observation returns
normally — the App UI then silently loses historical `prNumber → state`
resolution with no audit trail. This violates
`intelligence/rules/typescript.md` §REQUIRED ("every catch-and-continue
branch MUST warn with the reason") and the observability BLOCKER gate in
`migration.md`.

`ObservePRStateDeps` (`observe-status.ts:187-200`) carries no `Logger`. The
`log?: Logger` at `observe-status.ts:277` belongs to the separate
`ObserveChecksDeps` and is not reachable from this function.

## Solution

1. Add `readonly log?: Logger;` to `ObservePRStateDeps`. The `Logger` type is
   **already imported** at `observe-status.ts:18` — no new import needed.
2. Replace the empty catch with a WARN, mirroring the pattern already used by
   `observeChecks` in the same file (`observe-status.ts:334-344`):

   ```ts
   } catch (err) {
     deps.log?.warn("observe-pr-state: terminal pr-state cache write failed — continuing best-effort", {
       branch,
       prCount: closed.length,
       error: err instanceof Error ? err.message : String(err),
       cause: err instanceof Error && err.cause ? String(err.cause) : undefined,
     });
   }
   ```
3. Thread the logger through both call sites that supply `kv`:
   - `engine/pipeline/primitives/persist-output.ts:443` — change
     `{ prManager, vcs, kv, ctx }` to `{ prManager, vcs, kv, ctx, log: deps.log }`.
     `deps.log` is already in scope (used at `persist-output.ts:456`).
   - `engine/work-items/work-items.ts:630-635` — add `log: observations.log` to
     the `observePRState` deps literal. This requires adding
     `readonly log?: Logger;` to `SyncObservationDeps`
     (`work-items.ts:409-422`); `Logger` is already imported at
     `work-items.ts:12`.
   - `engine/pipeline/primitives/orphan-reconciler.ts:136` needs **no change** —
     it passes no `kv`, so the guarded cache block never executes there.
4. In the composition root `engine/entry.ts:378-388`, hoist the
   `const syncLog = contextLogger(logger, syncCtx);` currently on line 386 to
   **above** the `syncFilesToState(...)` call and pass `log: syncLog` in the
   observation deps object (alongside `branchPrefixFor` on line 384). Keep the
   existing `syncLog.info(...)` summary on the line after the call.
5. **Preserve the non-throwing behavior** — the catch must still swallow so a
   cache-write failure never breaks the observation.
